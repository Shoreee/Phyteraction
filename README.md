# VP Physics Hands

Unity 6000.4.7f1 / URP / Metal application for physical hands and Gaussian scene interaction.

- Open **apps/unity** in Unity Hub. The application scene is `Assets/Scenes/GaussianWorld.unity`. Without local Gaussian payloads it starts in the self-contained physics lab; unavailable model buttons are disabled.
- Runtime modules live under `Assets/Modules` with explicit assembly references. Content, scenes, prefabs and project settings are separate asset roots. SDK-managed configuration stays at the package-required `Assets/Resources` (PolySpatial) and `Assets/XR` paths.
- Export through **Physics Hands > Build > visionOS Xcode Project**. Output: `artifacts/builds/visionOS`. A normal build uses authored Unity assets and requires neither Python nor raw datasets. The lab also builds without the Gaussian payloads.
- Install offline dependencies with `python3 -m pip install -r tools/requirements.txt`. Each tool supports `--help` and resolves default inputs relative to the repository, independently of the working directory.
- Place original datasets in `data/raw/flower` and `data/raw/physflow/<scene>`; PhysFlow configurations belong in `data/raw/physflow/configs`. Prepared payloads are written to the corresponding directories in `data/processed`.
- Scene scale and preprocessing resolution settings are in `tools/preprocessing/scene_scales.json`. Changing them requires preprocessing and reimporting the corresponding model.
- Import prepared PhysFlow assets through **Physics Hands > Gaussian World > Reimport PhysFlow Assets**. The learned flower importer uses `Assets/Settings/FlowerBakeSettings.asset`, including its explicit target, cage parameters, mode count and Python executable. Open scenes are not used as import configuration.
- `training` is reserved for future external training work; no training framework is included.
- Build and verification artifacts are ignored under `artifacts`. Runtime CSV metrics use the platform persistent data directory. Raw datasets, virtual environments and Unity-generated state are not versioned.

Use **TREE** (keyboard **F10**) for the optional official SpeedTree research content; its model button toggles back to Gaussian content. TREE has no PAPER or ROOM mode. Use **LAB** (keyboard **T**) to enter the physics lab and **BACK** to return to the last model; model buttons and **1–9 / 0** select a model directly. **RESET / Backspace** releases grips, clears rounds and restores props, triggers and the spring target; **PAPER / P** and **ROOM / B** are unavailable in the lab. The ball, five cubes and handle use collision and sticky-skin friction only.

Four user-supplied MARATHON guns sit on side racks: each model has one **FRICTION** and one **COMPLIANT** copy, all weighing 500 g. Friction copies have no holding joints or snap anchors. Compliant copies capture a nearby authored palm frame during an active grasp or pinch; opening the raw tracked hand releases them. Finite drives align gradually with gravity, mass and collisions retained. Thumb, middle, ring and pinky close toward an authored pose subject to joint limits and contact; the index remains independently tracked. Keep the index extended while picking up, then curl it onto the physical trigger. The first model has a sliding trigger and the second a hinged trigger; both accept recent physical index contact. A nearby gripping palm can also actuate the trigger through independent raw index closure and motion along its pull direction; acquiring a gun with an already curled index does not fire it. Assistance applies a finite internal trigger load with equal opposite reaction, without moving finger bodies. Each shot requires a new pull after release and spring return. Both use the actual marked muzzle vertex. The 25 g, 24 m/s rounds are virtual test parameters, not calibrated real ammunition.

Rounds are 12 mm wide, 30 mm long cylinders with wider fading trails, swept collision queries and impact momentum. Launch recoil and impacts transfer the same projectile momentum (0.6 N·s at launch). Embedded rounds follow the struck body, including the eleven-body spring target. A fixed pool bounds round count and clears on reset or leaving LAB. A second hand can physically support a gun without adding another snap connection. Gun geometry, normals and UVs come from the supplied FBXs. Seven shared PBR material sets use the packed textures extracted from the supplied Blender project, with metallic/roughness channels converted for URP. Only collision proxies are decomposed; render triangles are retained. Mesh resources are shared by matching copies. Source hashes and import conventions are recorded in `research/OPTIMIZATION-2026-10-21.md`; local source FBXs are retained in ignored `data/raw/guns`.

The shared console and tabletop move together with gaze plus pinch. Touch buttons with the physical index fingertip; near-button contact takes priority over starting a drag. On visionOS, one spatial-pointer gesture owns a drag through release or cancellation; pointer IDs are rearmed on release because the provider reuses them; head-facing tracked-pinch fallback is used only when no spatial-pointer device exists. Backgrounding cancels placement and pauses custom GPU work until foreground permission returns. A hand touching a movable prop or near an eligible or occupied palm grip cannot simultaneously start a workbench drag. Remote grabbing and force fields are suspended in the lab and restored on exit. Desktop input: **Tab** selects a hand, **RMB + mouse / wheel** moves it, **G / LMB** grasps, **H** index-pinches, **Y** middle-pinches, **Q/E, R/F, Z/C** rotate, and **X** resets the simulated pose.

Each hand has one rounded dashed palm-offset arrow and a larger palm marker with 24 rectangular radial ticks that appear and disappear clockwise over approximately 0.3 seconds: white at 3 cm, yellow at 8 cm, red at 15 cm, with a 120 ms entry delay and 1 cm downward hysteresis. `HAND OFFSET` reports a valid but physically blocked target; `BAD TRACKING` reports actual tracking loss. Feedback is passive and does not weaken pursuit or release a grip on its own. All feedback geometry and its labels render over scene geometry, including Gaussians. The arrow appears only after every tick is visible. Interrupted animations retain current tick opacity; detached feedback objects finish their exit before releasing their resources. Object-side rings use the same rectangular ticks and animation to preview the nearest eligible free grip anchor as a palm approaches; they disappear on capture or when leaving LAB. The approach band starts at 1.5 times the configured capture distance, with 15 degrees of extra orientation tolerance; capture thresholds stay unchanged. Capture distance, orientation, handedness and occupancy are authored on object-side `GripAnchor` components.

XR thumb retargeting maps the three physical segments to `ThumbMetacarpal`, `ThumbProximal` and `ThumbDistal`. The distal orientation follows the `ThumbDistal`–`ThumbTip` direction; the authored auxiliary thumb base stays in its bind pose. Pose copies retain each rig's authored local bone lengths rather than copying metre-based tracking positions into the centimetre-based physics skeleton.

Normal and tracking-loss skins use 50% alpha transparency without depth writes. Each hand displays one toon-shaded physical skin, an outline hull, and its physical skeleton kept visible above the skin through a stencil mask and scene depth testing. Reference/ghost skins remain disabled. Neither skin nor skeleton casts shadows onto other objects. Physical hand colliders retain their original sticky-skin materials. Static scenery and neural contact suppress inward linear and angular pursuit while preserving tangential motion and withdrawal; movable props retain grasp pressure. The interactive rig uses 360 Hz PhysX steps with joint preprocessing disabled for unreachable tracked targets; drive acceleration remains finite. Per-bone `PhysicsJointDriver` tracking settings expose the response frequency, contact/free acceleration limits and angular acceleration limit. The current rig uses 60 Hz position response, 180 m/s² contact acceleration and 18,000 rad/s² angular acceleration; joints remain dynamic and constrained.

Realtime Gaussian interaction now uses a persistent tetrahedral material cage with finite-strain elastic energy and XPBD contact. Cage geometry comes from the moving reconstruction, enclosed voids are filled conservatively, and released fixed regions are retained. The source Young's modulus, Poisson ratio, density and normalized-space calibration are consumed without per-model stiffness overrides. Oriented boundary triangles with swept fingertip checks replace isolated point contacts; bearing constraints retain free rotation. Finite rigid-body mass/inertia, queued drive forces, zero-restitution velocity projection and an orientation guard are used in the same fixed tick; the hand loop has no GPU readback. Contact-free low-energy states sleep at their settled pose, including a rotated bearing. Distant reconstruction floaters retain their offset from their nearest material cell instead of receiving unbounded affine extrapolation.

This is an explicitly **non-destructive elastic approximation**, not an exact replay of PhysFlow's foam/plasticine/fluid/sand rheology. Anchored captured geometry is treated as its loaded rest equilibrium; scripted collapse, sequential release, plastic rest updates and fracture are absent. The original MPM components and source assets remain available for research but are disabled in the authored scene. PAPER is unavailable in the new mode. Flower retains its existing learned modal path. A full articulated implicit contact solve is not implemented; headset tracking/contact still requires device validation.

The nine PhysFlow MPM assets currently use **author initialization**, not optimized paper checkpoints. Flower uses its separate learned modal path. No material stiffness was hand-tuned in this revision. Training requires the [official PhysFlow checkout](https://github.com/zhuomanliu/PhysFlow), NVIDIA CUDA dependencies and scene guidance frames (`images_generated`). The pinned entry point requests an 8 GiB Taichi pool in addition to PyTorch allocations. The launcher reports Python, extensions, compiler and available CUDA memory before starting; an isolated Python 3.9 environment alone does not make training ready. The nine public dataset ZIP directories were inspected on 2026-10-22: each includes 49 `images_generated` guidance frames, but no optimized material checkpoints were found. Gaussian reconstruction PLYs are distinct from material optimization outputs. The public repository has no published GitHub releases. These findings describe the checked public locations, not a claim about unpublished author files. Preflight or launch the upstream trainer from any working directory:

```sh
python3 /path/to/repo/tools/materials/train_physflow.py hat --physflow-root /path/to/PhysFlow --check
python3 /path/to/repo/tools/materials/train_physflow.py hat --physflow-root /path/to/PhysFlow --epochs 10
python3 /path/to/repo/tools/materials/import_physflow_training.py hat --checkpoint /path/to/output/hat_ds1.0_ep10/ckpt/sim.json --training-commit 6beba6746fad4590f5b63ce6fa85c3b862b182d9
```

Use **Physics Hands > Gaussian World > Import Trained PhysFlow Materials** to apply the validated artifact. The importer checks scene, material, source/configuration hashes and units, records checkpoint provenance, and changes only material scalars. The supported upstream revision is `6beba6746fad4590f5b63ce6fa85c3b862b182d9`; its one-element material parameters are supported. Other revisions require schema verification before import, preventing spatial parameters from being silently averaged. Missing artifacts leave author initialization intact. Unity builds do not invoke training or require Python.

Per-frame CSV recording and full-particle quality readback are opt-in through `GaussianMetrics.recordCsv`. Leave it off for normal use; enable it explicitly for profiling. An optional diagnostics readout remains available. Rendering reuses depth order only when deformation, view orientation, model transform and visible count are unchanged; stationary modal geometry skips redundant uploads. Source Gaussian counts, SH and attributes are preserved. The realtime renderer clips faint tails below 2/255 to reduce transparent overdraw; set `GaussianRenderBinding.minimumContribution` to 1/255 before activation to restore the source cutoff. Vertex processing rejects only footprints already invisible under the existing opacity/frustum rules before computing SH. Profiler markers `PhysicsHands.Cage.Step`, `PhysicsHands.MPM.Step`, `PhysicsHands.MPM.ContactWait`, `PhysicsHands.MPM.GPU` and `PhysicsHands.Gaussian.Sort` distinguish simulation, synchronization and sorting costs.

Large Gaussian model payloads are intentionally excluded from Git: `Assets/Content/Gaussians/*.asset` and the `PhysFlow` model directory, including their matching metadata. To enable Gaussian content in a fresh clone, restore the full `apps/unity/Assets/Content/Gaussians` directory from an existing local project or a separately supplied model archive. Preserve paths and all `.meta` files: the authored scene, render bindings and bake settings reference their GUIDs. Small shared materials remain versioned.

A fresh clone can run and build the physics lab. Restore the excluded payloads to enable the ten Gaussian models. This repository does not host a model archive, and `git lfs pull` does not retrieve the excluded payloads. Alternatively, regenerate assets using the preprocessing and import commands above, then reassign any newly generated model and render assets in the scene and flower bake settings; regenerated GUIDs may differ.

TREE uses the official `Bush_Desktop` SpeedTree resource and its atlas from [Unity-Technologies/WaterScenes](https://github.com/Unity-Technologies/WaterScenes), pinned to `6032de37ee5cccfe5d86b5cf0959f66747de9342`. **The official tree assets are for non-commercial research only.** The source license, hashes and import metadata are versioned; licensed model/texture payloads and derived meshes/materials are excluded. Restore them with:

```sh
python3 /path/to/repo/tools/preprocessing/fetch_speedtree.py
```

Then run **Physics Hands > Import > Restore SpeedTree Research Mesh**. The importer updates `TreeAppearance.asset`, so regenerated payload GUIDs do not require scene edits. Missing payloads disable TREE while LAB remains usable. Only one original LOD mesh is used; source wind animation is disabled so visible motion comes from the shared physical solver. The small `TreeMaterialPrior.asset` transfers PhysFlow's author alocasia initialization; it is **not measured tree wood, an optimized checkpoint, or evidence of learned generalization**. Root fixation is derived from the imported geometry. The research record describes the calibration and held-out training/evaluation still needed.

Existing research and measurements remain under `research`; temporary migration and regression tools are not part of the final project.
